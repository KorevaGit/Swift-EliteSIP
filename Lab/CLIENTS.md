# Настройки клиентов для лаборатории

Все данные — для стенда **Asterisk 13.38.3** (`docker-compose.13.yml`), той же
версии, что на бою.

## Запуск

```bash
cd "/Users/koreva/Projects/Swift EliteSIP/Lab" && ./lab.sh up
```

Скрипт сам запустит Docker Desktop, если он не поднят, остановит лабу на
Asterisk 16 (она спорит за RTP-порты) и напечатает, куда подключать клиентов.

Вместе с учебным стендом FreePBX:

```bash
cd "/Users/koreva/Projects/Swift EliteSIP/Lab" && ./lab.sh up freepbx
```

Посмотреть состояние в любой момент: `./lab.sh status`. Остановить: `./lab.sh down`.

Наше приложение:

```bash
open -n "/Users/koreva/Library/Developer/Xcode/DerivedData/EliteSIP-gxdtafckxnqnnvbztvtbzwzglupz/Build/Products/Debug/EliteSIP.app"
```

## Адрес сервера

| Откуда подключаемся | Адрес | Порт |
|---|---|---|
| С самого Mac | `127.0.0.1` | `5060` |
| С телефона в той же сети | `10.171.3.84` | `5060` |

Порт `5070` тоже работает — он остался от прежних заметок. **Начинайте с 5060:**
сторонние клиенты подставляют его по умолчанию, а нестандартный порт часть из них
либо требует указывать отдельным полем, либо молча игнорирует — и регистрация не
проходит без всяких объяснений. Именно на это натыкались.

Адрес Mac в сети меняется при переподключении к другому Wi-Fi. Текущий:

```bash
ipconfig getifaddr en0
```

Править `externaddr` в `Lab/asterisk/config/sip.conf` руками больше не нужно:
`./lab.sh up` и `./reload.sh` подставляют туда текущий адрес сами. Но знать, чем
это грозит, стоит — Asterisk ставит этот адрес в SDP, и по устаревшему звук
уходит в никуда в обе стороны. Симптом обманчивый: звонок устанавливается и
завершается штатно, а разговора нет.

Если сеть сменилась при поднятой лабе, достаточно `./reload.sh`.

## Наше приложение (EliteSIP на Mac)

| Поле | Значение |
|---|---|
| Внутренний номер | `100` |
| Пароль | `elite100` |
| Домен / сервер | `127.0.0.1` |
| Порт | `5060` |
| Транспорт | UDP |

## PortSIP на iPhone

| Поле в PortSIP | Значение |
|---|---|
| Username / User name | `101` |
| Password | `elite101` |
| SIP Domain / Domain | `10.171.3.84` |
| Outbound proxy | оставить пустым |
| SIP Server / Proxy port | `5060` |
| Transport | UDP |
| Display name | любое, например `iPhone` |
| Кодеки | оставить G.711 (PCMU/PCMA), остальное можно выключить |
| SRTP / шифрование | выключить — пир 101 работает по открытому UDP |

Телефон должен быть в той же сети Wi-Fi, что и Mac. Брандмауэр macOS выключен,
порты опубликованы на всех интерфейсах — дополнительно ничего открывать не нужно.

Если нужен второй телефон — есть пир `102` с паролем `elite102`, настройки те же.

## Что можно набрать

| Номер | Что происходит |
|---|---|
| `600` | эхо-тест: слышно себя, лучшая проверка звука |
| `601` | сервер проигрывает файл — проверка приёма без передачи |
| `602` | тон 1004 Гц |
| `603` | принимает DTMF и произносит цифры обратно |
| `100`, `101`, `102` | звонок другому клиенту |
| `8000` | конференция ConfBridge |
| `22998` | заглушка «горячей раздачи» |

Позвонить с iPhone на Mac — набрать `100`. В обратную сторону — `101`. С M3
приложение входящие принимает: на экране появится плавающее окно, и каждый раз
в новом месте — это защита от кликеров по координатам.

Если в настройках включено подтверждение цифрой, вместо «Ответить» будет ряд
цифр, и принять вызов нужно той, что названа в подписи.

Проверить приём без окна, из консоли:

```bash
(cd Tools/sipcheck && swift run sipcheck --user 100 --password elite100 --duration 15 --answer)
```

## Если звука нет

Смотреть надо со стороны сервера — он единственный видит обе половины:

```bash
docker exec elitesip-lab13 asterisk -rx 'sip show channelstats'
```

* нули в `Recv` — до Asterisk не доходит поток от клиента;
* нули в `Send` — Asterisk не отправляет, обычно потому что не понял, куда;
* цифры в обеих колонках — медиа-путь исправен, дело в самом клиенте.

Журнал нашего приложения — вкладка «Диагностика», там весь обмен SIP и форматы
звука. Из командной строки то же самое:

```bash
"/Users/koreva/Library/Developer/Xcode/DerivedData/EliteSIP-gxdtafckxnqnnvbztvtbzwzglupz/Build/Products/Debug/EliteSIP.app/Contents/MacOS/EliteSIP" --log-to-stderr
```
