# Панель EliteSIP

Управление рабочими местами EliteSIP: сотрудники, номера, ключи активации и
предустановки.

Стоит **на локальном сервере конторы** и наружу не смотрит. В интернет уходят
только два объекта, и ни один не хранит секретов в открытом виде: файл
предустановок и пакеты активации — оба на Cloudflare R2, оба панель кладёт
исходящим запросом.

Разбор решений — [docs/DECISIONS.md](docs/DECISIONS.md). Формат того, что панель
кладёт наружу, и что читает приложение — [docs/CONTRACT.md](docs/CONTRACT.md).
Отложенное с причинами — [docs/ideas.md](docs/ideas.md).

## Как это работает

1. Администратор заводит номер (номер и SIP-пароль вбиваются руками — пир на
   АТС заводится отдельно и панелью не управляется), заводит сотрудника и
   назначает ему номер и предустановку.
2. Кнопка «Выпустить ключ» собирает пакет — номер, SIP-пароль, административный
   пароль конторы и предустановку, — шифрует его этим же ключом и кладёт в R2.
   Ключ показывается **один раз**: он же служит ключом расшифровки, и панель
   его не хранит.
3. Сотрудник вводит ключ в приложении. Оно вычисляет из ключа адрес пакета,
   забирает его и распечатывает. Пакет отдаётся один раз.
4. Дальше приложение к панели не обращается вовсе — только раз в полчаса тянет
   подписанный файл предустановок с R2.

## Запуск

```
cp .env.example .env        # заполнить доступы к R2
mkdir -p data secrets
docker compose run --rm panel keygen
```

`keygen` печатает три значения: приватный ключ подписи — в `secrets/signing.key`,
секрет сервера — в `secrets/server.secret`, оба правами `600`. Открытый ключ
вписывается в `Info.plist` приложения.

**Открытый ключ надо вписать в клиент до первой выкладки.** Сменить его у уже
настроенных машин нельзя — они перестанут принимать файл предустановок. Та же
беда, что с ключом Sparkle, и то же лечение: резервная копия в двух местах.

```
docker compose up -d
docker compose exec panel elitesip-panel admin eugene
```

Пароль читается со stdin, а не из аргумента: аргумент попадает в историю
оболочки и в список процессов.

## Настройки

Из окружения; секреты — **путями к файлам**, а не значениями, потому что
значение видно в `docker inspect` и в списке процессов.

| Переменная | Что | По умолчанию |
| --- | --- | --- |
| `ELITESIP_LISTEN` | адрес прослушивания | `127.0.0.1:8080` |
| `ELITESIP_DB` | файл базы | `/var/lib/elitesip/panel.db` |
| `ELITESIP_SIGNING_KEY_FILE` | приватный ключ подписи | `/var/lib/elitesip/signing.key` |
| `ELITESIP_SECRET_FILE` | секрет сервера | `/var/lib/elitesip/server.secret` |
| `ELITESIP_R2_ENDPOINT` | адрес R2 | — |
| `ELITESIP_R2_BUCKET` | бакет | — |
| `ELITESIP_R2_ACCESS_KEY_ID` | доступ к бакету | — |
| `ELITESIP_R2_SECRET_ACCESS_KEY` | он же | — |
| `ELITESIP_PUBLISH_DIR` | выкладка в каталог вместо R2 (стенд) | — |

## Интерфейс

Серверный HTML, один файл оформления, немного JavaScript без сборки и без
зависимостей. Язык macOS 26 воспроизведён своими средствами: готового
веб-набора для него не существует — Liquid Glass живёт в SwiftUI, — а чужой
пакет с npm означал бы дерево зависимостей на сервере, куда никто не смотрит
месяцами.

- **Светлая и тёмная темы.** По умолчанию как в системе; переключатель в
  нижнем углу боковой панели перебирает «как в системе → светлая → тёмная».
  Тема ставится до первой отрисовки, иначе тёмная система на мгновение
  получает светлую страницу.
- **Одна раскладка на все ширины.** Ниже 900 точек боковая панель уезжает в
  горизонтальный ряд с прокруткой — прятать разделы за раскрывашку нельзя,
  спрятанный раздел на чужом рабочем месте просто не находят. Ниже 620 таблицы
  становятся списками карточек: горизонтальная прокрутка таблицы читается хуже
  всего именно там, где экран меньше.
- **Стекло — улучшение, а не основа.** Где `backdrop-filter` не работает,
  поверхность остаётся матовой и читаемой.

## Бэкап

Два файла: база и `secrets/`. **Бэкап базы обязан шифроваться** — SIP-пароли
лежат в ней открытым текстом, и это принятое решение, а не недосмотр:
разбор в [docs/DECISIONS.md](docs/DECISIONS.md).

## Разработка

```
go test ./...
go vet ./...
```

Тесты не требуют ни сети, ни бакета, ни докера: выкладка за интерфейсом,
времена подменяются, база — временный файл.
