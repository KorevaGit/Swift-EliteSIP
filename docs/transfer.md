# Перевод звонка

M5 добавляет перевод поверх установленного SIP-диалога. Сигнализация остаётся
в `SIPCore`, а приложение показывает оператору ход операции и не объявляет
успех раньше сервера.

## Слепой перевод

1. Оператор вводит номер и подтверждает перевод.
2. `SIPUserAgent` отправляет внутри текущего диалога `REFER` с
   `Refer-To: <sip:номер@домен>`.
3. Ответ `202 Accepted` означает только, что сервер начал операцию. В интерфейсе
   это состояние «Сервер переводит…», а не готовый перевод.
4. Asterisk сообщает судьбу созданного INVITE запросом `NOTIFY` с телом
   `message/sipfrag`.
5. Только финальный 2xx в sipfrag считается успехом. 404, 486 и другие отказы
   остаются разговором с исходным собеседником и показываются оператору
   человеческим текстом.

Каждый NOTIFY получает `200 OK`. Если сервер принял REFER, но за минуту не
сообщил результат, операция заканчивается явным таймаутом. Повторный перевод
того же диалога до финального результата локально запрещён.

## Консультационный перевод

Протокольная основа уже есть: `SIPDialogIdentifier` строит значение
`Replaces`, а `SIPUserAgent.transfer(to:replacing:)` кодирует его как URI-header
в `Refer-To` по RFC 3891:

```text
Refer-To: <sip:602@pbx?Replaces=call-id%3Bto-tag%3Dremote%3Bfrom-tag%3Dlocal>
```

Для полного пользовательского сценария остаётся перевести хранение звонков с
одного `activeCall` на три адресуемые линии. Тогда порядок будет таким:

1. исходная линия ставится на удержание;
2. на второй линии оператор звонит адресату и консультируется;
3. REFER уходит по исходному диалогу, а Replaces описывает консультационный;
4. при отказе обе линии остаются доступны, при успехе локальные ноги
   завершаются.

До появления адресуемых линий интерфейс предлагает только реально работающий
слепой перевод; неработающей кнопки консультации в нём намеренно нет.

## Проверки

`TransferTests` покрывают:

- REFER внутри исходного диалога;
- точный Refer-To слепого перевода;
- percent-encoding Replaces;
- успешный NOTIFY и обязательный ответ 200;
- отказ созданного INVITE;
- разбор первой строки `message/sipfrag`.
